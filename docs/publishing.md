# Publishing & contributing

## Repository layout

```
palette-forge/
├── packages/palette-forge/   # the npm package
│   ├── src/
│   │   ├── color/            # convert · contrast · gamut · scale
│   │   ├── quantize/         # rng · sample · kmeans
│   │   ├── formats/          # the nine token emitters
│   │   ├── react/            # usePalette · useDropzone

│   └── test/                 # 101 tests

├── docs/
└── marketing/
```

## Local development

```bash
pnpm install
pnpm --filter palette-forge build   # the app resolves the package's dist/
pnpm dev                            # web app on :3000
```

```bash
pnpm test                           # vitest, all 101
pnpm --filter palette-forge test:watch
pnpm typecheck
```

The web app depends on `palette-forge` as `workspace:*`, so the package must be built at
least once before `pnpm dev` will resolve it.

## Build pipeline

`pnpm --filter palette-forge build` runs three steps:

1. **`tsup`** bundles four ESM entries (`index`, `react/index`, `node/index`, `cli`) with
   code splitting, so shared modules are emitted once.
2. **`tsc -p tsconfig.build.json`** emits declarations. Declarations are generated by the
   compiler rather than the bundler's TypeScript plugin, which keeps `.d.ts` output
   independent of bundler-version churn.
3. **`scripts/add-use-client.mjs`** re-adds the `"use client"` directive to
   `dist/react/index.js`. esbuild strips module-level directives when bundling; without this
   step, a React Server Component importing `palette-forge/react` fails at build time.

The CLI shebang and its executable bit are preserved by tsup automatically.

## Publishing

The package is ESM-only. That is deliberate: dual CJS/ESM builds carry the dual-package
hazard (two copies of the module, two sets of state) for a package whose consumers (Node
≥ 20, Next, Vite, bundlers) all handle ESM natively.

```bash
cd packages/palette-forge
pnpm build
pnpm test

npm pack --dry-run          # inspect exactly what ships
pnpm publish --access public
```

`prepublishOnly` runs the build and the tests, so a broken tree cannot be published by
accident.

### Release checklist

- [ ] `pnpm test` passes
- [ ] `pnpm typecheck` is clean
- [ ] Version bumped in `packages/palette-forge/package.json`
- [ ] `VERSION` constant in `src/cli.ts` matches. It is hardcoded so the CLI has no runtime
      dependency on reading its own `package.json`
- [ ] README examples still produce the values they claim (see below)
- [ ] `npm pack --dry-run` contains `dist/`, `README.md`, `LICENSE` and nothing else

### Verifying documented values

Examples in the README quote real output. When behaviour changes, re-derive them rather
than adjusting by eye:

```bash
cd packages/palette-forge && pnpm build
node -e '
import("./dist/index.js").then(({ scale, ensureContrast, contrast, rgbToOklch, fromHex }) => {
  console.log("scale:", JSON.stringify(scale("#4cc9f0")));
  console.log("oklch:", rgbToOklch(fromHex("#4cc9f0")).map(n => +n.toFixed(3)));
  const fixed = ensureContrast("#4cc9f0", "#ffffff");
  console.log("ensureContrast:", fixed, contrast(fixed, "#ffffff"));
});'
```

## Deploying the web app

Any Node host works; the app is not edge-only.

```bash
pnpm --filter palette-forge build
pnpm --filter @palette-forge/web build
pnpm --filter @palette-forge/web start
```

| Variable | | |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | Absolute origin, used for canonical URLs and OG metadata | `https://palette-forge-web.vercel.app/` |

Routes:

| | |
|---|---|
| `/` | static. The tool itself; extraction runs client-side |
| `/docs` | static |
| `/p/[palette]` | dynamic. Shared palettes decoded from the URL |
| `/p/[palette]/opengraph-image` | dynamic. The share card |
| `/api/extract` | dynamic. Node runtime, needs the filesystem/decoder path |

`/api/extract` decodes images in-process, so it must run on the Node runtime, not edge.

## Contributing

**Tests are the spec.** Colour maths is exactly the kind of code that looks right and is
wrong by 3%. Anything touching `src/color/` or `src/quantize/` needs a test that would fail
if the maths regressed: a round-trip, a known reference value, or a monotonicity check.

**Keep extraction deterministic.** Any randomness must route through `mulberry32` and an
explicit seed. A palette tool that returns different answers for the same image cannot be
cached, diffed or tested.

**Do not invent colours.** Two rules follow from this and are easy to break by accident:
clusters snap to medoids rather than means, and downscaling uses stride sampling with image
smoothing disabled. Both exist so every colour reported genuinely occurs in the source.

**Emitter output lands in someone's repo.** Readable generated text beats clever
abstraction; the emitters are plain string builders on purpose.
